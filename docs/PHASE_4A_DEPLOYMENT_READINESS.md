## Storage and backup decision

The [upstream MinIO repository](https://github.com/minio/minio) was archived on 25 April 2026 and declares itself unmaintained; the cached server identifies as RELEASE.2025-09-07T16-13-09Z. Production preflight refuses that known legacy digest. A supported storage/image/service and its licensing/security/operational arrangement must be chosen explicitly. No existing bucket was deleted, reconfigured or silently changed from versioned to unversioned.

The application's unique immutable keys can use a new approved private unversioned bucket. The backup adapter refuses versioned/suspended buckets to avoid incomplete recovery. All-version erasure remains tested, but versioned backup support has not been added. Choosing versioned operational storage requires a complete version-aware adapter and new restore evidence.

The coordinated backup's lock/ledger operations currently require the approved maintenance/schema-owner role. The template's SELECT-only `aia_backup` role is not sufficient. Linux evidence used `aia_migrator`, never ordinary web credentials. Approve the maintenance/custody arrangement or implement and rehearse a narrower privileged locking interface before production. Scheduled retention has no default: provide an approved absolute expiry or an approved duration plus policy reference. Event-specific cutoffs/holds must be reconciled before scheduling; a global duration does not override them.

Off-site setup must include an independently controlled encrypted destination, scoped credentials, transfer/checksum verification, expiry/delete evidence, separately recoverable custody keys and an actual isolated restore **from that destination**. Same-VPS copies and local restore success do not close this requirement. RPO/RTO, cadence and retention remain organisational decisions.
